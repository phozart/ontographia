SYSTEM OVERVIEW
System Name

BA Requirements & Delivery Workspace (working title)

System Purpose

Provide Business Analysts with a professional, end-to-end system to:

Capture business needs using BABOK-aligned structures

Model requirements visually (UML, BPMN, BIM)

Maintain traceability across requirements, models, and delivery tickets

Operate a lightweight internal ticketing and Kanban workflow

Produce BA-grade deliverables suitable for steering, governance, and audit

GLOBAL ASSUMPTIONS

Web-based application

Multi-project support

Role-based access control

Persistent storage

Visual modeling is data-driven, not decorative

EPIC 1 — PROJECT & WORKSPACE MANAGEMENT
Functional Requirements
FR-1.1 Project Creation

The system SHALL allow users to create a Project.

A Project SHALL include:

Project name

Description

Business context

Start date

Optional end date

Status (Draft, Active, Closed)

FR-1.2 Project Scoping

The system SHALL allow definition of:

In-scope items

Out-of-scope items

High-level objectives

Success criteria

FR-1.3 Role Assignment

The system SHALL support assignment of users to projects with roles:

Business Analyst

Product Owner

Stakeholder

Viewer

Permissions SHALL be role-based.

FR-1.4 Project Dashboard

The system SHALL provide a project overview page displaying:

Active requirements

Open tickets

Pending approvals

Linked models

Non-Functional Requirements
NFR-1.1 Usability

Project creation SHALL be achievable in ≤ 2 minutes.

NFR-1.2 Security

Only authorized users SHALL access project data.

EPIC 2 — BABOK-ALIGNED REQUIREMENT STRUCTURE ENGINE
Functional Requirements
FR-2.1 Requirement Types

The system SHALL support typed requirements, including:

Business Need

Business Requirement

Stakeholder Requirement

Solution Requirement – Functional

Solution Requirement – Non-Functional

Constraint

Assumption

Risk

FR-2.2 Requirement Attributes

Each requirement SHALL include:

Unique ID

Title

Description

Type

Priority

Owner

Status

Source

Acceptance criteria (where applicable)

FR-2.3 Hierarchical Relationships

Requirements SHALL be linkable using typed relationships:

derives from

refines

satisfies

constrains

depends on

FR-2.4 Validation Rules

The system SHALL enforce:

A Business Requirement must trace to at least one Business Need

A Solution Requirement must trace to a higher-level requirement

Non-Functional Requirements
NFR-2.1 Consistency

Relationship types SHALL be centrally configurable and reusable.

FINAL IMPLEMENTATION NOTE FOR CLAUDE

This system must be implemented as a data-centric platform, not a document editor.
Visual elements are views over structured entities.
Traceability is mandatory, not optional.
All modelling elements must have identity, type, and lifecycle.
